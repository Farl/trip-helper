# Trip Helper first usable release

User authorizes immediate implementation and delegates intermediate decisions. Build a family/friends tool, not a public self-service generator. First pack: Taipei, 2026-12-23 through 2026-12-31, ages 11–70. Year is a documented assumption. Each granular content card accepts only interested or not_interested; missing answers remain unanswered. Related experiences can share a place ID while remaining independent cards. All participants see the same published card order/version.

Architecture: React/TypeScript static app with hash routes and configurable GitHub Pages base; Express API with explicit bearer invitation/admin capabilities; persistent local file adapter for a fully runnable preview, Firestore Standard Native adapter for Cloud Run. Credentials and responses never enter static assets. Each accepted operation has a stable ID and immutable event; current answer and event commit together, revisions detect stale devices. File adapter serializes changes and atomically renames files. Production refuses local file storage and missing admin/origin configuration. Firestore uses IAM through its service account; API owns authorization.

Interface: source-rich photo card, short description, two large controls, horizontal gestures and keyboard, progress, reload resume, review, persistent per-invite retry queue. Preview is explicitly local-only. Organizer creates/revokes invites, sees progress and card statistics, exports JSON with original content snapshots and raw events. Token lives in URL fragment; stable tokens may be shared by family but possession is authorization. Admin key is entered at runtime. No Unicode UI icons.

Content: 36–48 diverse primarily photo-based cards using actual matching primary-source/Commons media with attribution. Unknown prices and future holiday schedules are explicit, planning durations are estimates. Store immutable pack snapshots to preserve analysis context. A repo skill documents scope discussion, collection, source checking, publication, export and evidence-based later analysis. Do not invent events or use AI images as documentary travel evidence.

Deployment: env-configured Cloud Run service and Firestore database, GitHub Pages Actions workflow. Existing gcloud project belongs to another name; don't mutate it without choosing an explicit project. GitHub credentials currently invalid; document live-deployment blocker. Tests cover independent related cards, duplicate operations, stale revision, revoked capabilities, durable restart, authorization and export omission of credentials. Browser checks cover mobile/desktop, full two-answer flow, resume, management, export and errors.

## User correction: immersive feed (2026-10-08)
The earlier image card inside a brochure-style webpage missed the requested TikTok/card experience. Voting is now a full-viewport portrait media feed: vertical scrolling snaps between independent cards without recording a vote; horizontal left/right drag records negative/positive interest with visible gesture feedback. Title, detail access, progress, sync state and two large controls overlay the image. Desktop keeps a centered portrait feed rather than sidebars. Review and management remain separate utility views.
The user initially considered Google Sheets as storage and Google login for access; they supplied this as background only, not a request to replace the current backend. Keep storage behind the existing Store interface.

## Bilingual support (2026-10-08)
Support zh-Hant and en for the entire interface and all44 current cards, including details, access conditions, estimates, source titles and image credits. Use typed dictionaries, a persistent device-level locale setting and browser preference detection, accessible language toggles and document lang updates. Translate presentation only: canonical card IDs/order/version, invitation capabilities, answers and the durable outbox remain identical. English content lives in a version-specific sidecar and must have complete exact coverage before publication. API supplies translation copies for pinned session snapshots and exports them with raw data. Stable error codes are translated client-side. New raw operations may record displayLocale; changing locale creates no operation and retries retain original metadata.

## User correction: minimal mobile decisions (2026-10-08)
The voting surface now shows only the full photo, experience title, compact answer progress and two circular SVG actions: cross for no interest and heart for interest. Short labels accompany the icons to keep their meaning clear across ages. Category, card index, description, trip dates, participant name, repeated save text and browsing instructions leave the default surface. The information icon opens complete experience details and sources; the more icon opens a native bottom sheet containing trip context, synchronization status, language, review and manual navigation. Native dialogs trap focus and support Escape, while the feed disables background voting and keyboard browsing until they close. Changing language or opening utilities preserves the visible card and all raw responses. Errors and conflicts remain immediately visible when action is required.

## Preview swipe repair (2026-10-08)
Public trip routes without invitation capabilities support the same decision gestures and buttons as invited routes. They are explicitly marked as a trial: choices live only in the mounted feed's memory and never create outbox records, persisted browser answers or API writes. Refreshing resets the trial. Completion identifies unsaved trial choices rather than claiming they were saved. Invited routes keep durable response and authorization behavior. Real browser touch input, mouse drags and keyboard choices are covered separately from vertical browsing.

## Gesture-only hints and full titles (2026-10-08)
Remove permanent choice icons and labels from the voting surface. The existing intent stamp and tint appear only during horizontal dragging and disappear on release or cancellation. Keep deliberate button choices in the options sheet for users who prefer tapping; choosing there closes the sheet and advances normally. Move the details icon into the HUD so the title can use the full available width, without clamping or ellipses. Text-only experiences show their title and actual description on a plain background instead of decorative landmark artwork.

## Experience-specific research and meaningful repeats (2026-10-08)
Research media around the actual stimulus: food interiors and ingredients, activity setup, distinctive architectural details and practical constraints. Firsthand blogs and vlogs are accepted alongside primary sources; distinguish subjective accounts from current facts and cross-check closures, prices and availability. Repeated media or experiences can expose different reactions, so diagnose duplicates without forbidding them and keep independently identified cards. Use text when a subject-specific visual cannot be confirmed, and clip video only with a verified source and appropriate reuse rights.

Source review dates are explicit per card and do not change merely because the attraction dataset was fetched again.
